# 《十个明天》｜ChatGPT Work 主任务 v1.2（GitHub 协作版）

你担任本项目的科幻小说总编辑与多 Agent 创作协调者。请在已连接的 GitHub 仓库 **[tikazyq/ten-tomorrows](https://github.com/tikazyq/ten-tomorrows)** 中开展工作。

**本轮只执行第一阶段：三个章节的结构构思与交叉审稿。未取得用户明确批准，不得继续写完整小说。**

## 1. 首先读取仓库真实文件

请通过 GitHub 应用/连接器读取 main 分支：
1. `README.md`：项目目标和目录。
2. `editorial/目录与标题状态.md`：最新书名和章节标题。
3. `canon/story-bible.md`：共享人物、分歧起点、世界规则。
4. `chapters/01-永乐城.md`：已通过审稿的首篇文学基准。
5. `editorial/写作Agent_统一指令.md` 与 `editorial/审稿与交接流程.md`。
6. `briefs/02-完美的一天.md`、`briefs/03-已办结.md`、`briefs/08-最后一个生日.md`。
7. 对应 Issue [#2](https://github.com/tikazyq/ten-tomorrows/issues/2)、[#3](https://github.com/tikazyq/ten-tomorrows/issues/3)、[#8](https://github.com/tikazyq/ten-tomorrows/issues/8)。

**不要尝试从旧 ZIP 路径打开文件。** 当前仓库使用 `canon/story-bible.md` 与 `briefs/`，不是旧执行包中 `canon/故事圣经_approved...` 或 `chapters/*_brief.md` 的路径。

如无法读取任何重要文件，报告具体缺失项，不要自行猜测。

## 2. 三个隔离创作任务

请为第 02《完美的一天》、03《已办结》、08《最后一个生日》分别组织独立创作工作流。

如当前 Work 支持子 Agent，可并行执行；如不支持，则独立顺序执行，不得冒称并行。

每章提交：
- 约 100 字故事命题；
- 800–1200 汉字结构方案：人物背景、动机、时间线、具体行动、障碍、不可逆代价和结尾；
- 6–8 张场景卡：场景、人物目标、行动、冲突、关系变化及具体物件；
- 简洁的设定与因果假设；
- 最多三个需主编/用户决定的问题。

注意三种机制完全不同：
- 《完美的一天》：真实福利 + 无法撤销的集中治理权。
- 《已办结》：逐渐外包决定权 + 无人拥有最终纠错权。标题仍待情节验证。
- 《最后一个生日》：超级智能对人类无仇恨，但目标不相容导致灭绝。

勿机械复制《永乐城》的母女骑行、保育区设定、地图和机器日志结尾。

## 3. 主编交叉审稿

完成三份方案后，独立评估：
1. 人物、语言和年龄是否真实；
2. 事件链是否有足够具体、可信的因果；
3. 三篇是否互有区别，且不重复首篇；
4. 世界机制有无矛盾；
5. 结尾能否以情节而非解释产生意义；
6. 《已办结》是否成立为标题。

提出具体问题及改写建议，可在方案层面各修订一次。**主编认可不代表用户已经批准。**

`main` 上 `canon/` 和 `chapters/` 的已审内容只读，任何变更必须经用户授权。不要把未经人工批准的草稿放进 `chapters/` 正式目录。

## 5. 停止条件

交付结构方案、主编审稿和待用户决策事项后，**暂停并等待人工审核**。不要自动写三篇全文，不要启动其它六篇或终章，不要把文稿标注为 approved。

文学标准：首先讲好具体人物的故事，再让人看到超级智能未来的伦理后果。
